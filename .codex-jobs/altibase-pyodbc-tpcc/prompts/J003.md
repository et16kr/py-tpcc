# Job J003: TPC-C transaction implementation

## Goal

Implement and validate the five TPC-C transaction methods for the Altibase pyodbc driver.

## Source Material

- `ALTIBASE_PYODBC_EXECUTION_DESIGN.md`
- Existing transaction implementations:
  - `pytpcc/drivers/postgresqldriver.py`
  - `pytpcc/drivers/sqlitedriver.py`
- Runtime transaction generation:
  - `pytpcc/runtime/executor.py`
  - `pytpcc/constants.py`
- Altibase driver from J002: `pytpcc/drivers/altibasedriver.py`

## Scope

- Modify `pytpcc/drivers/altibasedriver.py`.
- Implement:
  - `doDelivery()`
  - `doNewOrder()`
  - `doOrderStatus()`
  - `doPayment()`
  - `doStockLevel()`
- Keep pyodbc-only support.
- Do not change workload generation.

## Required Implementation

1. Read the source material before editing.
2. Add Altibase `TXN_QUERIES` using qmark `?` placeholders.
3. Use `LIMIT 1` only where already verified. For delivery, use `ORDER BY NO_O_ID LIMIT 1`.
4. Do not use PostgreSQL-specific `%s`, casts, or session settings.
5. Return `(value, retries)` from every transaction method.
6. Commit on success and rollback on exception.
7. Use bounded retry based on `max-retries` and `retry-delay`.
8. Do not retry deterministic implementation errors indefinitely. Log SQLSTATE/vendor code where pyodbc exposes them and immediately fail obvious syntax/conversion errors.
9. In `doNewOrder()`:
   - Reinitialize `all_local`, `items`, `item_data`, and `total` inside each retry attempt.
   - For intended invalid item rollback, call `rollback()` and return `(None, retries)`.
   - Insert `O_ALL_LOCAL` with a value Altibase accepts, not PostgreSQL `::integer` casting.
10. Ensure order status by customer last name uses the median customer behavior from existing drivers.
11. Self-review fetchone/fetchall `None` handling. Avoid `len(None)`.
12. Keep transaction code scoped to the Altibase driver.
