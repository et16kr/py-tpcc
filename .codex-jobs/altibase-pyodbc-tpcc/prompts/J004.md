# Job J004: Results integration and smoke runs

## Goal

Integrate Altibase into result summaries, add any needed cleanup/documentation, and run the final pyodbc baseline smoke checks.

## Source Material

- `ALTIBASE_PYODBC_EXECUTION_DESIGN.md`
- `ALTIBASE_TEST_NOTES.md`
- Result formatting: `pytpcc/util/results.py`
- Main runtime cleanup flow: `pytpcc/tpcc.py`
- Altibase driver and DDL from prior jobs

## Scope

- Add `AltibaseDriver` to the SQL DB result summary path in `pytpcc/util/results.py`.
- Add narrow single-client cleanup in `pytpcc/tpcc.py` if still needed.
- Update README or a small project note with pyodbc run commands.
- Run final reset/load/execute smoke checks.
- Do not add native `altibase-python-driver` support.

## Required Implementation

1. Read the source material before editing.
2. Update `pytpcc/util/results.py` so `AltibaseDriver` uses the same short SQL DB summary style as PostgreSQL drivers and calls `driver.getNumberWH()`.
3. If single-client pyodbc handles remain open, update `pytpcc/tpcc.py` with minimal `hasattr(driver, "cleanup")` cleanup in the single-client main path. Keep the change narrow and avoid altering multiprocessing semantics.
4. Update documentation:
   - Prefer a concise README section or project-local note that points to `ALTIBASE_PYODBC_EXECUTION_DESIGN.md`.
   - Include the pyodbc-only scope, DSN requirement, and example reset/load/execute commands.
5. Run final smoke commands from `pytpcc/` when local Altibase is reachable:
   - reset-only twice
   - load-only with `warehouses=1`, `scalefactor=100`, `clients=1`
   - execute-only with `warehouses=1`, `scalefactor=100`, `duration=30`, `clients=1`
   - combined reset/load/execute with the same small scale
6. Verify result output includes the Altibase tpmC one-line summary.
7. If local Altibase is unavailable, run static checks and document skipped live checks clearly.
8. Self-review for regressions to existing drivers.
