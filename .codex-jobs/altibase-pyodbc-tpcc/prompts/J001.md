# Job J001: Altibase DDL and config

## Goal

Create the Altibase-specific TPC-C DDL and pyodbc config example that later jobs will execute.

## Source Material

- `ALTIBASE_PYODBC_EXECUTION_DESIGN.md`
- `ALTIBASE_TEST_NOTES.md`
- Existing DDL: `pytpcc/tpcc.sql`
- Existing config examples: `pytpcc/CONFIG_EXAMPLE`, `pytpcc/MONGODB_EXAMPLE`

## Scope

- Add `pytpcc/tpcc_altibase.sql`.
- Add `pytpcc/ALTIBASE_ODBC_EXAMPLE`.
- Do not add `altibase-python-driver` support.
- Do not implement the Python driver in this job.
- Do not change existing non-Altibase DDL semantics.

## Required Implementation

1. Read the source material and existing schema file before editing.
2. Create `pytpcc/tpcc_altibase.sql` from the TPC-C table layout with these Altibase-specific constraints:
   - Use `SMALLINT` instead of `TINYINT`.
   - Use `DATE` instead of `TIMESTAMP` for `C_SINCE`, `H_DATE`, `O_ENTRY_D`, and `OL_DELIVERY_D`.
   - Do not use `TIMESTAMP DEFAULT CURRENT_TIMESTAMP`.
   - Do not include `DROP TABLE IF EXISTS`.
   - Do not include statement-level comments that can confuse simple `;` splitting.
   - Keep primary keys.
   - Keep lookup/performance indexes: `IDX_CUSTOMER`, `IDX_ORDERS`, `IDX_ORDER_LINE_TREE`.
   - Exclude foreign keys in the first version.
   - Exclude the nonessential `CUSTOMER(C_W_ID,C_D_ID,C_LAST,C_FIRST)` unique constraint in the first version.
3. Create `pytpcc/ALTIBASE_ODBC_EXAMPLE` with section `[altibase]` and at least:
   - `dsn = ALTIBASE_LOCAL_20101`
   - `user = PYTPCC`
   - `password = PYTPCC`
   - `connection-timeout = 5`
   - `max-retries = 20`
   - `retry-delay = 0.1`
   - `fast-executemany = False`
4. If local Altibase is reachable and an isolated schema can be created or safely reused, validate the DDL with pyodbc by executing the DDL statements, checking the 9 table names, inserting one `datetime.datetime` into a `DATE` column if practical, then cleaning up the isolated objects. Use only pyodbc.
5. If local Altibase is not reachable, or if schema isolation is unavailable with the current credentials, still run static checks and document the live-smoke skip reason:
   - verify the DDL has no `TINYINT`, no `TIMESTAMP`, no `DROP TABLE IF EXISTS`, and no `REFERENCES`.
   - verify exactly the expected 9 `CREATE TABLE` statements are present.
6. Update `ALTIBASE_PYODBC_EXECUTION_DESIGN.md` only if the implementation reveals a necessary correction.
7. Self-review the final schema for table order, column order, primary keys, indexes, and compatibility with `runtime/loader.py`.

## Verification

Run at minimum:

```bash
python3 - <<'PY'
from pathlib import Path
ddl = Path("pytpcc/tpcc_altibase.sql").read_text()
required = ["WAREHOUSE", "DISTRICT", "ITEM", "CUSTOMER", "HISTORY", "STOCK", "ORDERS", "NEW_ORDER", "ORDER_LINE"]
for bad in ["TINYINT", "TIMESTAMP", "DROP TABLE IF EXISTS", "REFERENCES"]:
    assert bad not in ddl, bad
for table in required:
    assert f"CREATE TABLE {table}" in ddl, table
assert ddl.count("CREATE TABLE ") == 9
print("static ddl check ok")
PY
```

If Altibase is reachable, also run a pyodbc DDL smoke against `ALTIBASE_LOCAL_20101`.
